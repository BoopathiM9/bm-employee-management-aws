1. Executive Summary

This project demonstrates an enterprise-grade, production-quality implementation of a 3-Tier Web Application hosted natively on Amazon Web Services (AWS). Designed and implemented by Boopathi Murugesan, the system addresses critical enterprise requirements: high availability across multiple availability zones, least-privilege security zoning, zero open inbound administrative ports, centralized secrets management, automated autoscaling, and fully automated CI/CD pipelines.

The business application is an Employee Management Portal allowing full lifecycle record management (CRUD operations, department filtering, pagination, and health analytics). Rather than relying on simple single-instance hosting, every tier adheres strictly to AWS Well-Architected Framework principles.

Key Security & Reliability Guarantees

• Zero Open Management Ports: SSH Port 22 is completely disabled. Secure administration is performed strictly via AWS Systems Manager (SSM) Session Manager.
• Zero Hardcoded Credentials: All database passwords are dynamically managed by AWS Secrets Manager with TLS/SSL encryption. No passwords exist in source code, Git, or User Data.
• Private-Only Application Subnets: EC2 compute instances have no public IP addresses and cannot receive direct traffic from the internet.
• Multi-AZ Fault Tolerance: Dual Availability Zone architecture (us-east-1a and us-east-1b) across ALB, EC2 Auto Scaling, and RDS PostgreSQL with synchronous replication.

4. Security Architecture & Zero-Secret Policy

Security was designed into the foundational infrastructure rather than added as an afterthought. The architecture enforces defense-in-depth across the network, compute, application, and identity perimeters:

Zero Hardcoded Credentials Architecture

1. Dynamic Generation: The database master credentials are generated using Terraform's cryptographic random engine during initialization and stored directly into AWS Secrets Manager (bm_db_credentials).
2. Runtime Secret Resolution: During boot, the Node.js application utilizes the AWS SDK v3 to query AWS Secrets Manager using its IAM instance role (bm_ec2_instance_role). No credentials ever touch source code, Git repositories, or environment configuration files.
3. Network-Chained Security Groups: The database security group (bm_db_sg) exclusively accepts port 5432 ingress from the backend security group (bm_backend_sg). Even if an external actor had database credentials, the database is physically unreachable from the public internet.

B. Automated GitHub Actions CI/CD

The project includes two continuous integration and continuous deployment workflows:

  • Frontend Pipeline (frontend-ci-cd.yml): Automatically triggers on commits to main modifying frontend code. Runs automated linting, builds the React production bundle, synchronizes assets to Amazon S3, and triggers a CloudFront cache invalidation.
  • Backend Pipeline (backend-ci-cd.yml): Executes 13 automated unit tests against the Node.js REST API. Packages the backend artifacts and performs rolling updates across the Auto Scaling Group instances via AWS Systems Manager without dropping incoming web requests.
  • Passwordless OIDC Authentication: GitHub Actions connects to AWS using OpenID Connect (OIDC) identity federation. No permanent AWS Access Key IDs or Secret Access Keys are stored in GitHub repository secrets.

7. Disaster Recovery & Cost Optimization Strategy

The architecture is built for production reliability while maintaining cost predictability:

  • Zone Failure Resilience: If an entire AWS Availability Zone experiences an outage, the Application Load Balancer shifts 100% of traffic to the healthy zone, and RDS automatically promotes the standby replica in under 60 seconds with zero data loss.
  • Cost Elimination via Terraform: When demonstration periods conclude, running terraform destroy in the deployment directory cleanly removes all provisioned AWS cloud assets, preventing ongoing operational charges.
  • Permanent Portfolio Demo: The standalone Vercel deployment remains permanently operational with its built-in client-side fallback storage, allowing mentors and evaluators to test the interactive portal indefinitely at zero cost.
